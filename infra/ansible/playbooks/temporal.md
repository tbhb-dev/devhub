# Temporal deployment

`temporal.yml` applies `docker_rootless`, `temporal_postgres`, `temporal_server` and `temporal_ui` in that order. Use the public alias inventory together with the private inventory. With `hosts: all`, the play accepts the Molecule platform's run ID. Currently, the public inventory contains only `edge-1`. Limit an operator deployment to `edge-1` if the inventory contains more hosts. Fresh installations aren't check-safe, following the predecessor roles.

The operator supplies `temporal_frontend_service` and `temporal_ui_service` as distinct `svc:` names in private inventory and provisions the daemon used by `tailscale`, Service approvals, tags, and grants. Port 7233 serves the frontend. `temporal_ui_loopback_port` defaults to 8080. Both Services use TCP forwarding to `127.0.0.1`, preserving the client Transport Layer Security (TLS) session to the frontend. This playbook renders no TLS termination flag. Command syntax follows the [`tailscale serve` reference](https://tailscale.com/docs/reference/tailscale-cli/serve). System units enable the forwarding after boot and withdraw it when stopped. The playbook manages no tailnet policy and never enables Funnel. Before changing a Service name or port, run removal with the previous values to withdraw the old forwarding.

Issue #30's current Scope moves scoped apply to #34. The combined deployment now permits `apply-scoped temporal` with the same restricted flags as `ssh` and `runner-pool`. The operator must check real tailnet exposure and mTLS at that deployment. The recorder used by Molecule proves only the rendered commands.

## Removal

`temporal-remove.yml` stops and disables the two tailnet forwarding units and removes their unit files. It then disables the installed Temporal user units and removes the three app containers. It also removes `temporal_network_name`. The user's daemon, account, unit files, certificates, data, and dumps remain. Run the dump service and confirm a completed SQL dump before removal. A later deployment can enable the retained units again. Removal affects only these resources. An unexpected network attachment causes Docker to refuse network removal rather than deleting another container.

## Cross-role contracts

The local #27 role confirms user `temporal` and home `/var/lib/temporal`. It confirms subordinate IDs starting at 655360, Docker data image `/var/lib/temporal-docker-data.img`, shared `temporal_network_name` defaulting to `temporal`, container `temporal-postgres`, units `temporal-postgres.service`, `temporal-postgres-dump.service` and `temporal-postgres-dump.timer`, data variable `temporal_postgres_data_dir` and dump variable `temporal_postgres_dump_dir`. The PostgreSQL role manages the network and supplies databases `temporal` and `temporal_visibility`, login `temporal`, and container DNS `temporal-postgres:5432`. Its second invocation of `docker_rootless` must remain idempotent with the explicit first invocation here.

Confirmed from #28: `temporal_server_frontend_port` defaults to 7233, `temporal_server_metrics_port` defaults to 8000, container `temporal-server` and user unit `temporal-server.service`. Confirmed from #29: `temporal_ui_loopback_port` defaults to 8080, container `temporal-ui` and user unit `temporal-ui.service`. Both roles use the same user, home, daemon, and network. They publish only on `127.0.0.1` and don't leave a persistent container for administration tools or extra enabled units. These names match the delivered roles. The removal lists in `vars/temporal.yml` are explicit. Add extra resources there. You can override these playbook variables with extra vars.

Versions and digest pins stay with their roles. Before applying the roles, the playbook copies `temporal_host_op_token_src` from the controller to `temporal_host_op_token_file`, owned by `temporal` with mode `0400`, and supplies the PostgreSQL environment file. A missing controller token fails a real apply with a provisioning message. Credential tasks suppress output and diffs. `temporal_host_certificate_items` maps `server` and `internal` to dictionaries containing `vault` and `item`. The managed host reads `ca`, `certificate` and `private-key` fields and the PostgreSQL login password into private files under `temporal_host_secret_dir`. The UI reads its own item through `temporal_ui_client_certificate_vault` and `temporal_ui_client_certificate_item`. Only the UI role has an `*_op_token_file` option today. PostgreSQL uses `temporal_postgres_op_environment_file`, and the server consumes prepared files. According to #28, the server owns `temporal_textfile_dir`, and this playbook doesn't deploy an exporter. Nothing may listen on `127.0.0.53:53`, which the runner egress policy permits for DNS.

## Molecule integration

The default scenario in `roles/temporal_ui/molecule/default` imports the deployment playbook from converge. It keeps #29's run-ID platform, per-role ephemeral state, `community.docker.docker_api` connection, copied CA preparation, credential stubs, and the Docker build file. Its sequence is `destroy, syntax, create, prepare, converge, idempotence, side_effect, verify, destroy`, without a check step. Separate volumes for `/var/lib/temporal` and `/var/lib/temporal-probe` avoid nested overlay filesystems. Prepare writes a controller-side stand-in token, and converge installs it through the deployment task. Side effect verifies its checksum, mode, and owner. Scenario inventory sets the ports to 7233, 8000 and 8080, `temporal_network_name: temporal`, and the Service names to `svc:example-temporal` and `svc:example-temporal-ui`.

After the CA and credential setup, prepare imports `temporal-prepare.yml`. It creates a second daemon for `temporal-probe` with a distinct subordinate ID range starting at 786432. It installs the recorder and saves the listener baseline. Scenario inventory disables separate Docker data images with `docker_rootless_data_size: ""` for both daemons.

Side effect runs #29's wrong-CA test and restores the valid certificate. It checks the Temporal `namespaces`, settings and UI isolation before importing `temporal-side-effect.yml`. That extension writes a real dump and checks both recorded TCP forwarding commands. It requires actual listeners on the three ports on `127.0.0.1` and rejects every newly added listener on another address. It then probes port 7233 through the second daemon's host gateway. The default `loopback` restriction in rootless Docker may provide the isolation without the runner egress table, as #30's refinement notes accept. A positive host connection to 7233 precedes the negative probe. The helper saves the refusal and dump checksum, then imports removal. The final verify imports `temporal-verify.yml` to check containers, network, enabled user units, forwarding unit files, retained PostgreSQL version files, and the unchanged latest dump.

`mise run test-tools` includes listener checker cases for wildcard IPv4, IPv6, a documentation-range interface, DNS-stub exposure and an absent frontend. Run `mise run lint-ansible` for the static playbook checks. Run the complete UI Molecule scenario only when all three Temporal roles and Docker are available.
